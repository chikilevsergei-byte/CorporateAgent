# 📋 План доработки CorporateAgent v3

> Приложение: десктопный (Swing) AI-ассистент руководителя проектов.
> Стек: Java + Swing GUI · DeepSeek/OpenAI-совместимый LLM · SQLite (sqlite-jdbc).
> Оценки ориентировочные. Итоговая стоимость ИИ-разработки: **20 млн токенов = 1 $**.

## ✅ Часть A — Что уже СДЕЛАНО (актуальное состояние)

### A1. Единый цвет текста кнопок — чёрный ✅
- `Ui.stylePrimary / styleSecondary / styleIcon / styleDanger` — приведены к чёрному тексту
  (danger остаётся красным, т.к. семантический). Добавлена константа `Ui.BLACK`.
- Точечный ручной `setForeground(Color.BLACK)` на ключевых кнопках (Отправить / Настройки / Новый чат).
- Компиляция exit 0.

### A2. Работа только с локальным SQLite + создание БД по файлам ✅
- **2.1** В чипах БД / списках — только реальные локальные SQLite-файлы (`type=sqlite`). Серверные типы не допускаются без JDBC-драйвера.
- **2.2 (интерфейс)** Кнопка «✨ Создать БД из файлов» в «⚙️ Настройки → Базы данных» (и блок «Способ 2» в `DbManagerView`) →
  `DbCreateFromFilesDialog` → многофайловый выбор (txt/md/csv/html/docx/pdf/xlsx/pptx) → `FileExtractor` →
  `Agent.createDatabaseFromFiles(...)` → схема `CREATE TABLE` (+ стартовые `INSERT`) через LLM → `DatabaseManager.createDatabase`.
- **2.3 (чат)** Ветка `database` в `Agent.processTask` при прикреплённых файлах реально вызывает
  `createDatabaseFromFiles(...)`. Имя БД берётся из запроса (`guessDbNameFromRequest`), результат регистрируется в чипах.
- **2.4 (гигиена)** При удалении БД удаляется локальный `.db`-файл и соответствующие `db_logs`, устраняя «осиротевшие» ресурсы.
- **Инфраструктура:** в `lib/` добавлены `slf4j-api`/`slf4j-nop`; авто-коммит sqlite-jdbc устранён
  (`conn.setAutoCommit(false)`), живой SQLite работает. Проверено вживую пользователем (CSV/XLSX → БД в UI и в чате).

### A3. Учёт токенов и защита от перерасхода ✅
- **`TokenBudget`** (`util/`): учёт `prompt+completion` из `usage` ответов DeepSeek; авто-сдвиг по дате;
  суточный лимит; формула **20 млн = 1 $**. Покрыто smoke-тестом (10/10 PASS).
- **`DeepSeekClient`** записывает `usage` (`record`) в каждом ответе.
- **`Agent.processTask`** останавливается без вызова LLM, если `TokenBudget.isExhaustedToday()`.
- **Чат:** после ответа показ расхода «⚡ использовано … · всего $…».
- **Настройки → Интерфейс:** поле «Дневной лимит токенов (0 — без лимита)» → `settings.json`
  (`daily_limit_tokens`), применение на старте (`App`) и при «Сохранить»; строка «Сегодня потрачено … лимит … осталось …».

### A4. Управляемый agentic-цикл записи в БД (function calling) ✅
- Встроенные функции **`db_query`** (только чтение: `SELECT/PRAGMA/WITH/EXPLAIN`) и **`db_execute`**
  (безопасная запись; `UPDATE/DELETE` без `WHERE`, `PRAGMA`, транзакции — отклоняются) в `ToolExecutor.executeBuiltinSql`.
- Показываются модели только при выбранной активной БД; маршрутизируются до/вместе с пользовательскими инструментами.
- Активация в `processTask` при выбранной БД; после tool-контура `autoUpdateDb` принудительно выключается (нет двойной записи).
- Системный промпт БД переписан: сначала `db_query` (факты), затем `db_execute` (запись с `WHERE`), затем подтверждение.
- Smoke-тест: функциональность охранников покрыта (итог 14/14 OK).

### A5. Качество контекста / безопасности / тесты (частично) ✅
- Обрезка истории под контекст-бюджет (`Agent.trimHistory`, `HISTORY_TOKEN_BUDGET`, заметка о потере раннего контекста).
- Выборочная выборка таблиц по релевантности (`Agent.buildDbContext`) — вместо всегда «всей схемы».
- `auto_update_db` по умолчанию **выключен**; авто-DML пропускает `UPDATE/DELETE` без `WHERE`.
- `executedTools` сделан потокобезопасным (как и общий `ToolExecutor`).
- **Smoke-тесты** (`test/corpagent/SmokeCoreTest.java`, без внешних фреймворков, запуск через `main`): 14 проверок OK.

### Группа C6 — 🔥 Улучшение пользовательского интерфейса в духе Apple/iOS (новое, финальный этап)

> чтобы оно **безошибочно напоминало Apple**: спокойно, уверенно, «неизбежно/привычно» для iOS-пользователя.

> (философия: нативный вместо кастомного, утончённый вместо выразительного, ясность и привычность прежде всего;
> «если сомневаешься — удаляй лишнее»).

**Дизайн-принципы для всей переделки:**
- Типографика **SF Pro**-подобная (системная читаемая; замена на доступные системные шрифты):
  иерархия через размер/начертание, а не цвет.
- Нейтральная палитра: почти-белый фон, системные серые, акцентные цвета — **экономно**
  (сейчас палитра «emerald/slate» — заметно чужеродна Apple).
- Прозрачность/размытие/глубина там, где уместно; **никаких резких рамок-контуров** — интервалы и группировка.
- Плавные переходы: затухание, лёгкое скольжение, спокойная смена масштаба; без «отскоков» и модных эффектов.
- Карточки — лёгкие и системные, без визуального шума; стандартная iOS-навигация (крупные заголовки, где уместно).

**Абсолютные табу по результату:**
- Чрезмерно «кастомные» компоненты, модные UI-примочки/эффекты, насыщенные градиенты, неоновые цвета,
  плотные перегруженные макеты, нестандартные шаблоны навигации.

**Пошаговый план переделки экранов (на каждом — замысел / структура / типографика / взаимодействие / обоснование по iOS):**

   - системная палитра почти-белого + серые шаги + точечный акцент (заменить emerald-дом на системный iOS-синий там, где уместно);
   - радиусы, отступы, «сплошные» системные кнопки (как iOS), группы-разделители в стиле iOS lists;
   - ввести системный читаемый шрифт/алиас (SF Pro-подобный либо системный).
2. **Главное окно / заголовок** (`MainFrame`): спокойный светлый шапка, крупный заголовок, кнопки в системном стиле.
3. **Боковая панель / список чатов** (`SidebarPanel`): вид iOS-списка, строки-ячейки (иконка, заголовок, время),
