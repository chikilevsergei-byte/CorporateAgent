# Руководство пользователя CorporateAgent 5.4.5 Portable

CorporateAgent — локальный помощник руководителя проектов с браузерным интерфейсом и подключением к облачной модели по API. Установка и перенос описаны в [инструкции запуска](INSTALL.md).

## Подключение модели

Откройте **«Настройки» → «Модель»**, введите **`1234`** и заполните параметры. Этот пароль фиксирован в исходниках и не шифрует папку `data`.

| Провайдер | Что указать |
| --- | --- |
| DeepSeek | API-ключ, доступную вашему аккаунту модель, Base URL. Предустановленный адрес: `https://api.deepseek.com`. |
| Яндекс ИИ студия | API-ключ или IAM-токен, соответствующий способ авторизации, Folder ID и имя либо полный URI модели. Предустановленный адрес: `https://ai.api.cloud.yandex.net/v1`. |
| Alibaba Qwen | API-ключ, имя модели и адрес API, соответствующие вашему региону и аккаунту. В приложении предустановлен `https://dashscope.aliyuncs.com/compatible-mode/v1`. |
| Другой, OpenAI-совместимый | Доступный вам совместимый API, его Base URL, модель и ключ. Совместимость зависит от конкретного сервера. |

Адреса в таблице — значения из этой версии приложения. Доступность модели, региона, квот и полномочий проверяется на стороне вашего провайдера. Base URL вводится **без** завершающего `/chat/completions`.

Для Яндекса сначала заполните ключ и Folder ID, затем нажмите **«Загрузить модели из Яндекс AI Studio»** или введите имя модели вручную. Используйте каталог и доступы, выданные вашему аккаунту. IAM-токен временный: при истечении срока его придётся заменить.

Нажмите **«Проверить подключение»**. При успешной проверке нажмите **«Сохранить»**. Обращения к API могут расходовать квоты и средства вашего аккаунта. Встроенные локальные проверки приложения не подтверждают работоспособность вашего реального API.

## Первый чат

1. Нажмите **«Новый чат»**.
2. Добавьте нужный контекст: навыки, инструменты или базы данных.
3. Напишите задачу с ожидаемым результатом и ограничениями.
4. Проверьте ответ и созданные файлы перед использованием.

Пример запроса:

> Помоги составить список рисков внедрения новой информационной системы. Для каждого риска укажи причину, последствия, владельца и действие. Если данных о проекте не хватает, задай вопросы.

Вопросы по методологиям можно начать кнопками **«Вопрос по LPG»** и **«Вопрос по ИТ»**. Встроенные методологии создаются при первом запуске; ответы модели следует сверять с исходными материалами.

## Проект

1. Нажмите **«Создать проект»**.
2. Укажите название и описание.
3. Выберите новую базу проекта или существующую базу.
4. Проверьте данные мастера и создайте проект.

Мастер создаёт проектную базу/связь с базой и семь рабочих чатов:

- паспорт проекта;
- риски;
- план проекта;
- статус проекта;
- протоколы встреч;
- подготовка к УК;
- проверка страницы проекта в Confluence.

Название чата про Confluence обозначает сценарий работы. Оно не означает, что подключение к вашему Confluence настроено или что приложение автоматически имеет доступ к страницам.

Начните с паспорта: внесите цель, ожидаемый результат, сроки, участников и ограничения. Затем переходите к рискам, плану и статусу, используя контекст своего проекта.

## Файлы и документы

- Прикрепляйте файлы через элемент загрузки в чате.
- Поддерживаются извлечение текста и данных из TXT/MD/CSV/HTML, DOCX/PDF/XLSX/PPTX. Сложная вёрстка может извлекаться частично; распознавание сканов не заявляется.
- Для презентации попросите создать PPTX, для таблицы — XLSX. Если сценарий использует шаблон, сохраняйте папку `Шаблоны` в составе приложения.
- Результаты сохраняются в `data/output` и доступны через интерфейс. Проверяйте содержимое, оформление и полноту результата.

Примеры:

> Подготовь Excel-реестр рисков для текущего проекта на основе согласованных данных.

> Создай презентацию со статусом проекта: цель, выполненные работы, отклонения, риски и следующие шаги. Отсутствующие данные пометь явно.

Приложению не требуется установленный Microsoft Office для генерации файлов. Для просмотра результата нужен подходящий просмотрщик или офисный редактор.

## Базы данных

В разделе баз можно создавать и подключать SQLite-базы, просматривать таблицы, выполнять доступные операции импорта/экспорта и делать резервные копии. Встроенные базы методологий предназначены для чтения.

1. Создайте базу проекта или подключите существующую.
2. Откройте просмотр таблиц и убедитесь, что это нужная база.
3. Подключите базу к чату как контекст.
4. Перед операциями, меняющими данные, сделайте резервную копию и проверьте результат.

Для переносимой работы храните собственные базы внутри `data/databases`. Если база находится вне папки приложения, её нужно переносить отдельно и переподключать.

## Навыки, инструменты и заметки

- **Навык** задаёт инструкции для определённой задачи. Создайте его в настройках и выберите в контексте чата.
- **Инструмент** описывает доступное агенту действие. Доступность внешней команды зависит от компьютера: пользовательские Python/shell-инструменты могут требовать отдельно установленный Python или другие программы. Эти внешние программы в Portable-релиз не входят.
- **Заметки** подходят для рабочих записей рядом с чатами.

Подключение инструмента или внешнего API не происходит автоматически при распаковке релиза.

## Где хранятся данные

| Папка или файл | Содержимое |
| --- | --- |
| `data/config.json` | Настройки модели и сохранённый ключ API. |
| `data/*.json` | Чаты, проекты, навыки, инструменты и другие метаданные. |
| `data/databases` | Встроенные и созданные внутри приложения базы. |
| `data/output` | Созданные документы. |
| `data/backups` | Резервные копии. |
| `launch-logs` | Журналы запуска. |

Файлы данных не зашифрованы самим приложением. При работе с облачным API текст запросов и выбранный контекст передаются выбранному провайдеру. Используйте только данные, которые разрешено отправлять в этот API.

Резервная копия настроек интерфейса в окне настроек **не заменяет** резервную копию всей папки `data`: она не является полной копией чатов, проектов и ключей.

## Обновление и резервная копия

1. Завершите работу через `Stop.bat` / `Stop.command`.
2. Сохраните копию старой папки приложения.
3. Распакуйте новый релиз в отдельную папку.
4. Перенесите `data` из остановленной копии той же версии Portable или версии с подтверждённой совместимостью формата.
5. Запустите новую копию и проверьте чаты, проекты и базы.

Прямой перенос данных из старой v3 в v5.4.5 этим релизом отдельно не проверен. Сначала работайте с копией данных. Порядок переноса между Windows и macOS приведён в [инструкции запуска](INSTALL.md#завершение-работы-и-перенос).

## Ошибки API

| Ошибка | Что проверить |
| --- | --- |
| 401 | Ключ, выбранный способ авторизации, срок IAM-токена. |
| 403 | Права аккаунта и доступ к каталогу/модели. |
| 404 | Base URL и имя/URI модели. |
| 429 | Квоты и ограничения частоты запросов. |
| Тайм-аут / нет соединения | Сеть, корпоративный прокси, доступность API. |

При обращении за помощью укажите ОС, выбранный архив и текст ошибки без ключей и личного содержимого. Не прикладывайте целиком `data/config.json` или папку `data`.
